# Мок-API лиги

Инструмент разработки: полный набор данных, чтобы пройти весь сайт, когда
в настоящей базе ещё мало контента.

```bash
npm run mock       # поднять мок на :8099
npm run dev:mock   # dev-сервер сайта, смотрящий на мок
```

Две команды в разных терминалах. Настоящий бэкенд при этом не нужен и не
затрагивается.

## Что в датасете

| | |
|---|---|
| Соревнования | 3: завершённый чемпионат с плей-офф, идущий чемпионат, будущий турнир |
| Команды | 12 — с логотипами и без, с городом и без, одно очень длинное название |
| Игроки | 217 (5 страниц по 50 — проверка пагинации), вратари, защитники, нападающие |
| Заявки | 433 — номера живут в заявке и различаются между соревнованиями |
| Матчи | ~94, из них ~67 сыграно; часть без времени и места |
| Протоколы | ~1650 строк со вратарскими показателями |

Что специально покрыто:

- **Флаги главной ВКЛЮЧЕНЫ** (`show_standings`, `show_bracket`) — в реальной
  базе они выключены, и блоки таблицы и сетки на главной иначе не увидеть.
- **Канонический плей-офф** 1/4 → 1/2 → финал с победителем — на десктопе
  включаются соединители сетки.
- **Ничьи с буллитами** — проверка `extra_points` в таблице и чипа «по буллитам».
- **Сыгранный матч без протокола** — счёт внесён, состав по игрокам ещё нет.
- **Игроки, сменившие команду** между сезонами — по две записи в разбивке
  `by_team` и разные номера.
- **Игрок с полностью пустой карточкой** — без даты рождения, позиции и хвата.
- **Медиа генерируются на лету** (SVG) — иначе путь «логотип есть» не проверить.

## Почему данные вычисляются, а не прописаны

Таблица, лучшие игроки и статистика игрока **считаются из матчей и протоколов**
по тем же правилам, что на бэкенде: победа 2 очка, ничья 1, +1 за буллиты;
в таблицу идёт только `stage: matches` с обоими счетами; в «лучших» — все стадии.

Если прописать их руками, счёт в шапке матча разойдётся с протоколом, а таблица
с результатами — и сайт будет выглядеть сломанным по вине данных, а не кода.
Сумма голов в протоколе каждой команды равна её счёту, а пропущенные вратарём —
счёту соперника.

Генератор детерминированный (фиксированный сеед), поэтому после перезапуска
цифры те же и скриншоты сравнимы. Даты считаются от сегодня — демо всегда
выглядит «серединой сезона».

## Проверка пустых и битых данных

Этот мок — «всё хорошо и много». Отдельные состояния (пустая таблица при
наличии матчей, `player: null`, дубль `player_id`, чужой `team_id`, буллиты на
неравном счёте) удобно проверять, подменив нужные ручки: сервер маленький,
таблица маршрутов — обычный объект в `server.mjs`.
